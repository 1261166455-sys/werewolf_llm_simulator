# werewolf_llm_simulator 狼人杀 LLM 模拟器

A simple game emulated the classic Werewolf game, allowing LLMs to play

一个基于 FastAPI + WebSocket 的**十二人局**狼人杀操作台：12 个座位可以由**真人**和**大模型（LLM）**任意混合占用，可以在浏览器里实时观战、发言、竞选警长、投票和进行夜间行动。

## 功能特点

- **真人 / 模型混合对局**：每个座位单独切换为「真人」或「模型」，也可以让 12 个模型同时自动对战。
- **浏览器操作台**：实时显示发言、投票、夜晚行动与完整文字记录；警长（★）、警徽状态和已自爆狼人数直接显示在状态栏。
- **私有信息隔离**：狼人刀人、预言家验人、女巫用药、守卫守护不会进入公共记录，只在轮到该座位时显示在私有面板，并在该座位回答后清除；发送给模型的观察也按座位裁剪。当前所有连接的浏览器共享同一个操作台视图。
- **狼人互认**：轮到某位狼人操作时，棋盘上其余狼队友会显示为「狼阵营」（不会显示「狼人」或「狼王」——狼只认得同阵营，不认得谁是狼王），换人操作后立即恢复为未知。
- **全中文 + 中英切换**：界面、系统提示以及发送给模型的内容都能随时切换语言。
- **计时统计**：对局进行中顶栏显示「总用时」（整局时长）与「当前行动」（当前玩家的决策耗时，决策结束后归零重新计时）；导出 JSON 的 `timing` 字段记录整局时长、逐次行动耗时和逐玩家汇总，便于离线分析。回放不计时。
- **导出与回放**：一局结束后可导出存档，之后离线重放整局，**回放不会调用模型、不需要联网**。
- **身份显示开关**：可选择是否公开显示每名玩家的身份。

## 快速开始

### 1. 安装依赖

推荐使用 conda（环境名 `werewolf`，对应本仓库的开发环境）：

```bash
conda create -n werewolf python=3.14 -y
conda activate werewolf
cd engine
python -m pip install -r requirements.txt
```

也可以继续使用 `venv`：

```bash
cd engine
python3 -m venv venv
./venv/bin/python -m pip install -r requirements.txt
```

依赖只有两项：`fastapi`、`uvicorn[standard]`。

### 2. 配置模型与密钥

**模型设置全部写在 `engine/models.json` 里，页面上不能改（只能查看）。** 没有这个文件时，所有座位
都使用 `ds_key.txt` / 环境变量里的那一个模型，行为和以前完全一样。

仓库自带的 `models.json` 就是当前默认配置（下面的示例省略了 `version` / `note` 和 `_comment` 注释字段）：**0、1 号座位用 DeepSeek V4.1（`deepseek-flash`，
思考强度 `max`），其余座位沿用原来的聊天模型**（即 `ds_key.txt` / 环境变量里的那一个），
密钥都来自 `ds_key.txt`：

```json
{
  "default": "",
  "models": {
    "ds4.1-flash": { "kind": "deepseek", "model": "deepseek-flash",
                     "reasoning_effort": "max", "max_tokens": 8192 },
    "gpt":   { "kind": "openai", "model": "gpt-4o-mini", "api_key_env": "OPENAI_API_KEY" },
    "kimi":  { "kind": "compatible", "model": "kimi-k2-0905-preview",
               "base_url": "https://api.moonshot.cn/v1", "key_file": "moonshot_key.txt" },
    "claude": { "kind": "anthropic", "model": "claude-sonnet-4-5",
                "max_tokens": 2048, "api_key_env": "ANTHROPIC_API_KEY" }
  },
  "seats": { "0": "ds4.1-flash", "1": "ds4.1-flash" }
}
```

完整字段：

| 字段 | 含义 |
| --- | --- |
| `kind` | `deepseek` / `openai` / `anthropic` / `compatible`（任何 OpenAI 兼容网关） |
| `model` | 模型名，例如 `deepseek-flash`、`deepseek-v4-pro`、`gpt-4o-mini`、`kimi-k2-0905-preview` |
| `base_url` | 接口地址；`deepseek`/`openai`/`anthropic` 有默认值，`compatible` 必须写 |
| `api_key` | **直接把密钥写在这里**（最省事；此时不要提交这个文件） |
| `key_file` | 从文件读密钥，相对路径相对于 `models.json` 所在目录 |
| `api_key_env` | 从环境变量读密钥，例如 `OPENAI_API_KEY` |
| `temperature` / `max_tokens` / `timeout` / `json_mode` / `reasoning_effort` | 可选覆盖；思考强度 `off`/`low`/`high`/`max` |

> **思考模型要给足 `max_tokens`。** 思考内容（`reasoning_content`）和最终 JSON 共用同一个输出预算：
> 预算被试完时，接口会返回 `finish_reason="length"` 而 `content` 是空的。程序会明确报出
> 「ran out of N tokens while still thinking」并**自动把预算放大 4 倍重试一次**（上限 32768），
> 所以不会再莫名其妙地空回复；但把 `max_tokens` 设成 8192 这样的值可以省掉这一次浪费的调用。

顶层还可写 `"default": "<profile>"`（未列出的座位统一用它）与自由文本 `note`；
profile 内部的 `_comment` / `note` 会被忽略，可用来写注释。

**同一局里可以混用不同厂商**：

```json
{
  "models": {
    "ds4.1-flash": { "kind": "deepseek", "model": "deepseek-flash", "reasoning_effort": "max" },
    "gpt":         { "kind": "openai", "model": "gpt-4o-mini", "api_key_env": "OPENAI_API_KEY" },
    "kimi":        { "kind": "compatible", "model": "kimi-k2-0905-preview",
                     "base_url": "https://api.moonshot.cn/v1", "key_file": "moonshot_key.txt" }
  },
  "seats": { "0": "ds4.1-flash", "1": "gpt", "2": "kimi" }
}
```

规则要点：

- 座位没列在 `seats` 里 → 用 `default`；`default` 为空 → 用 `ds_key.txt` / 环境变量里的模型（即以前的行为）。
- 同一个 `kind` 的 profile 不写密钥时，自动复用 `ds_key.txt` 里的那把钥匙；**不同 `kind` 不会借用别人的钥匙**
  （`LLM_API_KEY` 是通用变量，只在同 kind 时用），必须自己指定，优先级
  `api_key` → `key_file` → `api_key_env` → 同 kind 的全局配置 → 该厂商的常规环境变量。
- 页面右上「模型与座位」里有 **查看模型配置**（只读，列出每个 profile 的模型/思考强度/密钥来源，
  **不会显示密钥本身**）与 **重新读取配置**（改完 `models.json` 免重启）。
- 「测试连接」会把这一局真正会用到的每个模型各测一次。

也可以继续只用 `ds_key.txt`：

```text
sk-你的密钥
# 或
api_key  = sk-你的密钥
model    = deepseek-chat          # 不写则用默认的 deepseek-chat
base_url = https://api.deepseek.com/v1
kind     = deepseek
```

> ⚠️ `ds_key.txt`、`*_key.txt` 已被 `.gitignore` 忽略。**如果在 `models.json` 里直接写 `api_key`，
> 那个文件就不要再提交**（仓库自带的 `models.json` 不含任何密钥，测试会检查这一点）。
> 密钥只会进入进程内存，不会打印到日志，也不会发送到浏览器。

### 3. 启动

```bash
# conda 环境（推荐）
conda activate werewolf
cd engine
python run.py

# 或 venv
./venv/bin/python run.py
```

脚本会读取密钥、自动挑选空闲端口，并在服务可访问后打开浏览器（默认 <http://127.0.0.1:8000/>）。


## 操作台使用说明

1. **设置座位**：在「模型与座位」中把每个座位设为「真人」或「模型」；也可用「全部模型 / 全部真人」
   一键切换全部 12 个座位。座位用哪个模型由 `models.json` 决定（标题行会显示「ds4.1-flash ×2 ·
   deepseek/deepseek-chat ×10」这样的分配概览），页面不提供修改入口。
2. **查看 / 测试**：点「查看模型配置」可展开只读的模型清单（模型、思考强度、token 上限、密钥来源）；
   点「测试连接」会把本局真正用到的每个模型各测一次；改完 `models.json` 点「重新读取配置」即可生效，无需重启。
3. **开始游戏**：点「新游戏」。轮到真人时页面下方出现输入框；轮到模型时自动请求并显示「模型思考中…」。
4. **观战**：发言、投票、竞选、遗言与夜晚行动实时刷新。状态栏会显示「警长 / 无警长 · 上警：… · 已自爆 n 狼」，
   警长座位在棋盘上带 ★。需要回答是非题（是否上警、是否自爆、是否移交警徽、发言顺序）时，
   操作区会出现「是 / 否 / 跳过」按钮。未公开的身份显示为 `??`，可用「公开显示身份」开关随时切换；
   「显示提示词」可查看发送给模型的完整提示；「显示模型思考过程」会把每个模型在行动前的推理
   （以及它顺手写在 `speech` 里的分析）以 `[私]` 标记插入公共记录，顺序是「先想法、后行动」，
   例如 `[私] 推理：今晚刀守卫` 紧接 `[私] ↳ 玩家8 选择了 5 [击杀]`。思考模型返回的思考过程
   （`reasoning_content`）会自动补进该玩家的「推理」里，所以这一项对 `deepseek-flash` 这类模型尤其有用；
   「显示完整日志」则进一步包含所有私有信息（守护、刀人、查验、用药等），便于复盘整局。
   其中「公开显示身份」「显示提示词」「显示模型思考过程」「导出附文本记录」由服务端保存，刷新后保持；
   「显示完整日志」只是当前页面的显示开关，刷新后恢复关闭。
   页面下方是**固定信息条**（操作区 + 私有信息），不会随日志滚动；日志在新消息到来时自动贴底，
   向上翻阅时则停在你正在读的位置，滚回底部即恢复自动跟随。
5. **导出 / 回放**：一局结束后点「导出本局」保存到 `engine/replays/`；在「导出文件」下拉框中选择后点「回放所选」即可离线重放，也可点「回放上一局」直接重放刚结束的一局。
   勾选「导出附文本记录」后，会额外写一份同名的 `.txt`：包含全部日志、私有信息（标 `[私有]`）、
   模型思考与理由、以及角色/结局的文字版说明，方便人工复盘；`.txt` 只是阅读稿，**不能用于回放**，
   `.json` 才是唯一的可重放存档。
   `.json` 会记录导出时的规则版本（当前为 `2.1`）。规则版本不一致的旧回放文件仍会列在下拉框中，
   但会标注「不可回放」并禁止选择：录制的答案对应的是旧规则的提问顺序与语义，强行重放会得到
   一局不同的游戏。唯一可回放的条件是文件中的 `rule_version` 等于当前 `engine.GameRule.Version`。
   `.json` 的 `timing` 字段保存计时数据：`total_seconds` 是整局耗时，`players` 汇总每名玩家的
   行动次数、总耗时、平均与最长单次耗时，`actions` 按顺序记录每次决策的座位、身份、决策类型、
   轮次、阶段、开始时间与秒数。回放是重放过程而不是真实对局，因此不计时，`timing` 为 `null`。
6. **切换语言**：页面右上角可随时切换中英文。系统提示、引擎日志和已显示的界面文本会同步翻译；模型已经返回的内容保持原语言，不会被重新翻译。

## 游戏规则

完整规则见 [rule.md](rule.md)，要点如下（当前规则版本 `2.1`）：

> **规则审查提示**：狼刀已按审查建议改为“每夜至多一刀”（规则版本 2.1）：狼队按座位顺序提议、被提议最多者死亡，平票或全部放弃则无人死亡；旧的“每只狼各指一人、被指者全部死亡”多刀变体已被移除。其余平衡性、实现偏差与 P0/P1/P2 修改计划见 [doc.md](doc.md)。

- 12 名玩家（P0–P11），角色随机分配：**狼人 ×3、狼王 ×1、预言家 ×1、女巫 ×1、守卫 ×1、猎人 ×1、平民 ×4**。
- **夜晚顺序**：守卫守护 → 狼队商议刀人 → 预言家验阵营 → 女巫用药 → 结算。
  - 守卫可以守自己，但不能连续两晚守同一人；守护挡狼刀，不挡毒药；同守同救判定死亡。
  - 女巫全局只有一瓶毒药和一瓶解药；解药只能救当晚被狼杀的人，第二晚起可以自救；毒药可对任意非己存活玩家使用。
  - 狼队共同商议：3 狼 + 狼王按座位顺序各提议一名存活玩家（可以看到此前队友的提议），被提议最多者死亡；平票或全部放弃则无人死亡。可以提议同阵营的狼人甚至自己。
- **白天**：公布死亡 → 判定 → （仅第一天）竞选警长与遗言 → 按警长指定的顺序发言 → 投票放逐 → 判定。
  - 狼人可在自己发言时自爆：发言保留、跳过当天其余发言与投票、直接进入下一夜晚；两只狼自爆后警徽作废。
  - 警长的票计 1.5 票；警长出局时可以把警徽移交给任意存活玩家或撕毁。
- **技能**：猎人被放逐或被狼刀死时可以开枪（被毒死不能）；狼王仅在被放逐时可以开枪。
- **胜负判定**：
  - 好人胜利：存活狼人数为 0。
  - 狼人胜利：所有神职（预言家、女巫、守卫、猎人）出局，**或**所有平民出局。
  - 平局：超过 10 轮仍未分出胜负。

## 实现状态

### 已实现

- **12 人标准局规则**：3 狼 + 1 狼王 + 4 神职 + 4 平民；守卫 → 狼人 → 预言家 → 女巫的夜晚顺序；警长竞选、1.5 票、警徽移交/撕毁；狼人自爆；猎人/狼王开枪；屠边胜负与 10 轮平局。
- **真人 / 模型混合对局**：12 个座位可独立切换；每个座位可绑定 `models.json` 中的不同 profile；支持 DeepSeek、OpenAI、Anthropic 和任意 OpenAI 兼容网关。
- **模型容错**：JSON 修复、非法动作回退、思考预算耗尽时自动放大预算重试、`reasoning_content` 回收。
- **Web 操作台**：WebSocket 实时推送、公开/私有信息隔离、模型思考与提示词查看、中英文切换、固定信息条、断线重连。
- **对局记录**：固定随机种子（`seed`）决定角色分配；回放通过导出的 `seed` + 答案序列复现整局，不调用模型；支持导出 `.json` 回放和可选 `.txt` 阅读稿。
- **测试**：`tests/run_all.py` 共 135 个用例，覆盖规则、整局不变量、桥接、隐私、回放、导出和模型配置。

### 尚未实现 / 后续可做

- **多房间与鉴权**：当前是单进程单对局（`ui.CURRENT`），所有连接的浏览器共享同一张桌子；没有登录、房间或观众/玩家权限区分。
- **对局中途存档/恢复**：目前只能导出已结束的对局；服务重启会丢失进行中的游戏。
- **回放控制**：只能按固定间隔重放，没有暂停、拖动进度、单步；导出文件只能从服务端 `replays/` 选择，不支持浏览器上传/下载。
- **批量模拟与评测**：没有 headless/批量对局入口，也没有跨局胜率、投票、发言或模型决策质量的统计。
- **可配置规则**：人数和角色配比目前固定在 `PLAYERS_COUNT` / `GameRule.Roles`，页面不能新建规则集。
- **模型与工程化**：没有流式输出、取消、token/费用统计；依赖未锁定版本，也没有 CI、`pyproject.toml` 或打包配置。
- **文档**：`engine/doc.md` 保存规则/机制审查、缺陷清单与后续修改计划；当前规则细节以 `rule.md` 与 README 为准。

### 已知问题

- **第一天黎明的判定顺序**：如果第一夜结束时已经满足胜负条件，当前实现仍会先进行警长竞选（并可能触发猎人开枪），之后才判定胜负；这与 `rule.md` 和上文「公布死亡 → 判定 → 竞选警长」的顺序不一致。只影响第一天夜间就直接结束的极端对局。

## 常见问题

**Q：启动时提示「未找到密钥」，模型座位不动？**
A：确认 `engine/ds_key.txt` 存在且第一行是完整密钥（`sk-` 开头）。真人座位不受影响，可以先只用真人测试。

**Q：端口被占用？**
A：脚本会自动使用之后的空闲端口，请以启动信息中「页面」那一行的地址为准。

**Q：模型返回的内容解析失败？**
A：程序会自动尝试修复 JSON，若仍不合法则退回一个合法动作，不会卡死。可点「测试连接」查看具体错误原因。

**Q：回放需要联网或密钥吗？**
A：不需要。回放是本地重新推演，完全不调用模型。
