## 0. 结论摘要

### 0.1 一句话结论

当前引擎实际运行的是 **“每只狼各指一人、所有被指者死亡”的多刀变体**，不是标准 12 人单刀狼人杀。这个变体在理性狼人 + 最基础协调下严重偏狼；同时投票、警长、自爆、信息集和结算顺序还有多处放大狼队优势或隐藏规则的缺陷。

### 0.2 关键数字

用现有 `tests/support.Driver` 做 500 局快速对照（`pass=0.1`，关闭自爆；不是严格均衡，仅看量级）：

| 策略 | 狼胜 | 好人胜 |
|---|---:|---:|
| 随机刀 / 随机票 | 335（67.0%） | 165（33.0%） |
| 协调刀（不重复刀非狼）/ 随机票 | 496（99.2%） | 4（0.8%） |
| 四刀 + 只把白天投票设为“全知” | 467（93.4%） | 33（6.6%） |
| 单刀代理 + 只把白天投票设为“全知” | 217（43.4%） | 283（56.6%） |

- “全知投票”是诊断：让好人投票时知道阵营，夜间技能仍随机；不代表真实玩家水平。
- “单刀代理”：只让第一个存活狼出刀，其余跳过；不是完整的狼队共识机制，只用于隔离“刀数”变量。
- 结论：**每人一刀是最大杠杆**；即使只改这一项，也需要同时修投票/信息规则，否则仍有大量偏狼机制。

### 0.3 最高优先级缺陷（按严重性）

1. **狼刀并集**：4 个无成本致命行动/夜，好人只有 1 个守卫 + 1 次解药 + 1 个预言家信息 + 1 次条件枪；攻击方 4 行动 vs 防守方 1–2 行动。
2. **投票机制**：平票不出人 + 无 quorum + 实时票数泄露 + 完整票型不公开；狼队可以用 4 票制造/利用平票，好人无法读票。
3. **警长竞选**：候选人不能投票、无 runoff、平票无警长、唯一候选人自动当选；高赌注 plurality 容易被 4 狼集中票和好人分票击穿。
4. **自爆**：狼人获得免费的“投票否决权”；两狼自爆后警徽作废的惩罚不单调，可能反而帮狼。
5. **信息结构**：LLM observation 缺少完整票型、警长选举、候选人发言历史、枪击/自爆/警徽事件；却泄露实时票数；人类和 LLM 的公开信息集不一致。
6. **同守同救**：守卫 + 女巫解药 = 目标死亡，是反协调/非单调规则，惩罚好人合作。
7. **胜负/结算/和局**：第一天先竞选后判胜负；同时胜利优先级隐藏；平局实际在第 11 天黎明；多死结算顺序未定义。
8. **狼队治理**：狼王对队友隐藏 + 允许刀狼/自刀，存在单只狼破坏团队策略的问题（优先级较低）。

### 0.4 建议决策

先决定产品目标，再决定改法：

- **目标 A：标准 12 人狼人杀**
  - 狼队每夜单刀（共识/多数）。
  - 白天同时秘密投票，投后公开完整票型。
  - 警长竞选改为全员投票/approval/runoff，降低或制衡警长权力。
  - 增加被放逐/夜间死亡遗言或死亡留言。
  - 修第一天顺序、同时胜利优先级、平局时点。
  - 推荐作为默认方向。

- **目标 B：保留多刀娱乐变体**
  - 必须在 README/提示词中明确标注“多刀狼/狼人优势变体”，不要再称“标准 12 人局”。
  - 同时改狼胜利条件（例如要求神和民都清空，而不是二选一）或增加好人保护资源。
  - 仍然必须修投票、信息集、自爆和结算顺序，否则只是“更快的狼胜”。
  - 不建议用这个变体的胜率做平衡评估；可以作为压力测试/娱乐模式。

## 1. 当前规则（按引擎实际执行）

> 本节描述的是 `engine.py` 当前行为，不是建议目标。行号以 2026-10-19 的代码为准，后续可能漂移。

### 1.1 角色与阵营

| 项目 | 当前值 |
|---|---|
| 总人数 | 12（座位 0–11） |
| 平民 | 4 |
| 狼人 | 3 |
| 狼王 | 1 |
| 预言家 | 1 |
| 女巫 | 1 |
| 守卫 | 1 |
| 猎人 | 1 |
| 狼阵营 | 3 狼 + 1 狼王 = 4 |
| 好人阵营 | 4 神 + 4 民 = 8 |

角色随机分配；`GameRule.Roles` 必须与 `PLAYERS_COUNT` 一致（`engine.py:1101-1114`）。

### 1.2 夜晚

顺序：**守卫 → 狼人（含狼王）→ 预言家 → 女巫 → 结算**（`GameRule.Night`，`engine.py:553-555`）。

- **守卫**：守护一名玩家或空守；可以守自己；不能连续两晚守同一人；不能守已出局者。守护挡狼刀，不挡毒。
- **狼人**：每只存活狼各指一名玩家或跳过；可以指狼/自己；所有被指者都会死亡（除非被守卫挡刀/女巫解药救）。被指者列表是并集，重复目标去重。
- **预言家**：验一名自己之外的存活玩家的阵营；狼王验为狼。
- **女巫**：看到今晚被狼人指名的所有目标；可以毒任意非己存活玩家；可以救今晚被狼刀的一名玩家；第一夜不能自救；毒死的目标不能被任何方式救回；守卫守护 + 女巫解药同时作用于同一目标时，目标死亡（“同守同救”）。
- **结算**：`end_night` 按“狼刀 → 解药 → 毒药”的顺序修改状态（`engine.py:712-754`）。

### 1.3 白天

实际顺序（`begin_day` + `GameRule.Day`）：

1. 公布昨夜死亡名单，并把这些玩家改为 `Exit`。
2. 第一天：进行警长竞选。
3. **胜负判定**（当前实际在这里发生，`engine.py:889-893`）。
4. 第一天：昨夜死亡玩家发表遗言。
5. 存活玩家按警长指定的顺序发言；狼人可以在自己发言时自爆。
6. 存活玩家投票放逐；警长 1.5 票；平票不出人。
7. 胜负判定。
8. 若未结束，进入下一夜晚。

狼人自爆：发言保留；自爆者立即出局；跳过当天余下发言和整个投票；直接进入下一夜晚。若全局累计 >= 2 只狼自爆，警徽在第二只自爆的当天被强制移除。

### 1.4 警长

- 仅第一天竞选。
- 所有存活玩家选择是否上警；候选人发言；**非候选人投票**；唯一最高票当选；平票或无人竞选则本局无警长。
- 只有一名候选人时，该候选人自动当选（不投票）。
- 警长票计 1.5 票。
- 警长出局时可以把警徽移交给任意存活玩家，或撕毁；没有存活候选人时强制撕毁。
- 两狼自爆后警徽作废。

### 1.5 技能与胜负

- **猎人**：被投票放逐或被狼刀死时可以开枪带走一名存活玩家；被毒死不能开枪；被其他方式杀死不能开枪。
- **狼王**：仅在被投票放逐时可以开枪带走一名存活玩家；夜里被刀死、被毒死、被枪死、自爆都不能开枪。
- **女巫**：全局一瓶毒药、一瓶解药。
- **好人胜利**：存活狼人数 = 0。
- **狼人胜利**：存活神职数 = 0 **或** 存活平民数 = 0。
- **平局**：`cycles > 10` 时判平；实际发生在第 11 天黎明（`engine.py:1053`）。

### 1.6 容易忽略的隐藏执行细节

1. **夜晚死亡在 `end_night` 才结算。** 当晚被狼刀/毒死的守卫、狼、预言家、女巫仍能完成当晚行动。例如被刀的预言家仍能验人，被刀的女巫仍能用药。
2. **狼刀是并集，不是共识单刀。** `WolfAction.execute` 把每个狼的目标追加到 `night.wolf_kills`；`wolf_do_night` 遍历所有存活狼（`engine.py:200-206`、`638-648`）。
3. **模型的顺序决策会看到中间结果**：
   - 后行动的狼看到前面狼的刀口（`ui.py:847-849` 的 `fact_pack_named`）。
   - 后竞选者看到前面谁已经上警（`engine.py:763-766` + `ui.py:875`）。
   - 后投票的模型看到实时票数（`engine.py:987-989` + `ui.py:832-834`）。
4. **投票允许弃权和自票，且没有最低票数/quorum。** 如果其他人都弃权，1 票也可能是唯一最高票并直接放逐（`engine.py:981`）。
5. **第一天实际是“公布死亡/死亡触发 → 竞选 → 判定 → 遗言”**，与 `rule.md:60-62` 的“公布 → 判定 → 竞选 → 遗言”不一致；`README.md:253` 已列为已知问题。
6. **发言顺序不是真正绕警长一圈。** 实现为“警长先，然后其余座位全局升序或降序”（`engine.py:912-917`），不是“从警长开始顺时针/逆时针”。
7. **警徽移交没有公开日志。** `police_badge_transmission` 改变 `state.day.the_police`，但只打印“警长死亡”，不打印新警长；UI 通过状态刷新显示，公开文字记录不完整（`engine.py:811-843`）。
8. **多死结算按座位号顺序。** `begin_day` 的 `deaths` 列表按 `players.items()` 顺序（0–11）生成；猎人开枪、警徽移交可能形成链式反应，顺序不同会改变结果，但规则没有定义。

### 1.7 决策时序与信息集

| 决策 | 引擎顺序 | 中间信息是否暴露给后续玩家 |
|---|---|---|
| 守卫守护 | 单角色 | 私有 |
| 狼人刀人 | 普通狼（座位序）→ 狼王最后 | 后行动的狼通过 `fact_pack_named` 看到前面刀口 |
| 预言家查验 | 单角色 | 私有，结果进入 `memory` |
| 女巫用药 | 单角色，狼刀之后 | 看到全部狼刀目标；其他玩家看不到 |
| 警长上警 | 存活玩家按座位序逐个询问 | 后询问者看到 `sheriff_candidates` 的当前部分列表 |
| 警长投票 | 非候选人按座位序 | `police_voting_result` 不进入 observation；只有最终警长可见 |
| 发言 | 警长定序 | 公开发言；自爆会截断后续 |
| 放逐投票 | 存活玩家按座位序 | `vote_result` 立即更新；后投票的 LLM 看到实时计数；完整 ballots 不公开 |
| 死亡/开枪/警徽 | 死亡列表按座位号；`on_exit` 递归 | 公开日志只覆盖部分事件；observation 缺少结构化公开事件 |

> **这是当前规则文本没有定义的“第二层游戏”。** 哪些决策同时、哪些顺序、顺序中暴露什么，直接改变均衡；必须在规则层明确，并由人类/LLM 共享同一信息集。

## 3. 博弈论诊断

### 3.1 狼刀并集：4 个无成本致命行动 vs 1–2 个防守行动

每只狼的击杀对狼队是 **无成本的公共品**：跳过是弱劣策略，杀非狼是弱占优；4 只狼等于每夜 4 个致命行动。好人只有：

- 守卫 1 次/夜；
- 女巫解药 1 次/局；
- 预言家 1 次/夜的信息；
- 猎人 1 次条件枪。

即使守卫和解药完美错开，首夜最多保 2 人，仍会死 2 人；之后通常只剩守卫 1 人，无法覆盖 3–4 刀。狼队唯一的协调问题是“别选重复目标”，而后行动的狼能看到前面刀口，协调成本几乎为零。提示词甚至直接告诉狼“分头刀会死更多人”，等于免费提供了协调信号。

这还是 **析取 vs 合取** 的胜利条件：

- 狼：`神全灭 OR 民全灭`；
- 好人：`狼全灭`，并且必须同时守住神/民两条边。

狼可以集中打一条边，好人必须覆盖两条边；攻击方 4 个行动，防守方 1–2 个，结构上就是碾压。

**修改方向**：改成每夜一杀（共识/多数），或保留多刀但把狼胜利条件改为“神和民都清空”并增加好人保护资源。单刀是最直接、最标准的修法。

### 3.2 投票：平票不出人 + 无 quorum + 实时票数 + 缺失票型

- **平票不出人是“现状偏好”**：4 狼是一个有共同利益的稳定投票 bloc，8 好人没有私聊、没有党鞭、信息不完整；好人一旦分票，狼队就能制造或利用平票。无出人等于狼队白得一夜，而好人需要每天都有唯一最高票，容错率远低于狼队。这是典型的 **少数否决 / 现状偏好**：有夜间击杀权的一方从“无作为”中获益。
- **实时票数泄露给后投票者**：引擎按座位顺序逐个收票并立即更新 `vote_result`，LLM observation 又把当前计数暴露给下一位投票者。最后一位投票者可以 bandwagon，也可以故意制造平票；这已经不是“同时秘密投票”，而是 **最后行动者优势** 的序贯投票博弈。人类和 LLM 看到的信息还不一样，公平性也被破坏。
- **好人看不到完整票型**：`DayHistory.vote_result` 其实保存了 `[count, voters]`，但 `ui.py:832-834` 只把计数给模型；警长选举的 `police_voting_result` 更是只存 `candidate -> count`（`engine.py:784`），根本没有“谁投了谁”。狼人杀最核心的公共信息就是票型；没有票型，好人无法识别投票联盟，等于在玩一个信息残缺的游戏。
- **允许弃权且无最低票数**：如果其他人都弃权，1 票也能成为唯一最高票并放逐；小团体可以用集中投票 + 好人弃权/分票实现“少数统治”。

**修改方向**：同时秘密提交；投后公开完整 ballots；设置最低票数/quorum；平票改前两名 runoff 或随机平票者出局；禁自票（或明确允许并测试）。

### 3.3 警长竞选：高赌注 plurality + 候选人被剥夺投票权

- 候选人不能投票，只有非候选人投票。极端情况下：11 人上警，唯一非候选人是“独裁者”；12 人全上警，直接无人当选；只有 1 人上警则自动当选。
- 没有 runoff，平票直接无警长；4 狼可以集中投一个狼候选，8 好人一旦分票就可能输掉警长。警长又同时拥有 **1.5 票 + 发言顺序 + 警徽移交**，一次协调失败的代价是整局性的。
- 上警是顺序询问的，后面的玩家能看到前面谁已经上警；这又是一个未声明的“后手优势”。
- 这是典型的 **entry game + spoiler effect**：好人越多上警，好人选民越少，狼队 4 票的相对权重越大；而“平票无警长”又给了狼队一个否决选项。

**修改方向**：全员投票（候选人可投他人但不可投自己）或 approval/ranked choice；前两名 runoff；平票随机或重投；上警同时秘密提交；降低警长权力（例如只保留发言顺序，或 1.5 票改为 1 票）；警徽被撕毁后考虑重选。

### 3.4 自爆：狼人的免费“投票否决权”

- 狼在自己发言时自爆，发言保留，但当天余下发言和整个投票都被跳过，直接进入夜晚。
- 如果这只狼本来就要被投出，自爆的死亡成本与放逐相同，却额外获得了：销毁票型信息、阻止好人投出另一只狼、保住狼王/关键狼。若它本来不是目标，则是牺牲一只狼救更重要的狼。
- “两狼自爆后警徽作废”不是一个单调惩罚：如果警徽在好人手里，作废反而帮狼；如果在狼手里，才伤狼。它只在第二次自爆后生效，无法约束第一次“免费否决”。
- 狼警长 + 早置位自爆还可以截断当天大部分发言，把议程设置权和程序性否决叠加在一起。

这是博弈论里的 **outside option / strategic exit**：一个即将输掉投票的玩家可以主动退出并改变后续博弈，使好人的投票威胁变得不可信。

**修改方向**：自爆后剩余玩家继续投票（只跳过自爆者自己的发言/投票）；或自爆使狼队下一夜少一刀；或只允许“当前票数最高”的狼自爆；或给好人补偿性公开信息（例如公开自爆者的具体狼种）。惩罚应当始终伤害狼队，而不是取决于警徽在谁手里。

### 3.5 信息结构：狼人信息多，好人信息少，LLM 与人类不是同一套信息

- 狼队有私聊级的互认 + 顺序刀口信息；好人只有公开发言和预言家一次查验。
- 模型 observation 缺少完整票型、警长选举票型、候选人发言历史、枪击/自爆/警徽移交等公开事件，却在投票过程中泄露实时票数。
- 这正好和推理游戏需要的信息结构相反：**投票时给得太多，投票后给得太少**。好人无法根据“谁投了谁”识别联盟，狼人却可以根据实时票数优化最后一票。
- 遗言只在第一天夜晚死亡时存在；之后的夜间死亡和被放逐者都没有遗言。预言家如果第二夜被杀，或没有提前跳身份就被投出，累积的查验信息直接消失。这使预言家的私有信息高度易腐，理性策略会偏向早跳（然后被多刀狼杀死）或沉默（然后好人失去信息）。
- `earlier_rounds` 不包含第一天候选人发言和警长选举结果，模型跨天后会“忘记”警长竞选；`fact_pack_named` / `fact_wolves_killed` 在白天还使用 “Tonight”，属于过期事实。
- 人类玩家看 UI 日志，LLM 看 observation；两者公开信息集不同，这会直接破坏用模拟器评测 LLM 推理能力的有效性。

**修改方向**：建立 **单一公开事件流**（死亡、枪击、自爆、警徽移交、警长选举、完整票型），人类和 LLM 都从同一份公开状态渲染；投票期间隐藏实时票数，投票结束后公开完整 ballots；候选人发言和警长选举写入历史；增加被放逐者/后续夜间死亡的遗言或有限“死亡留言”；修正白天过期事实的时态。

### 3.6 同守同救：反协调、非单调，惩罚好人合作

守卫和女巫是同一阵营，却不能沟通；规则却规定“守卫守护 + 女巫解药 = 目标死亡”。这意味着女巫的一次“救人”可以把原本被守卫救下的人变成死亡，**更多保护反而降低生存率**，违反机制设计里的单调性。女巫不知道守卫目标，理性上可能因此不敢用解药；这是一个隐藏的负外部性/反协调陷阱。

“毒药不能被任何方式救回”是单调的，没有问题；问题在“同守同救”。

**修改方向**：改为解药优先/守护与解药同时作用时目标存活；或者让女巫能看到守卫目标；如果一定要保留“重叠致死”，至少把它做成公开、可计算的博弈，而不是隐藏陷阱。

### 3.7 胜负、结算顺序与和局：隐藏优先级、额外一夜、可拖延

- 第一天实际先竞选再判定，和规则文本相反；如果第一夜已经满足胜负条件，仍会多走竞选。
- 同时满足胜负条件时，代码先判好人胜（`engine.py:1036-1050`）。如果最后一狼和最后一神/最后一民同时死亡，或垂死的狼王/猎人开枪造成双方条件同时成立，当前是好人胜，但规则文本没有写这个优先级。垂死开枪到底在胜负判定之前还是之后，也没有明确。
- `cycles > 10` 才判平，实际是第 10 天结束后还会走第 11 夜；而提示词说“最多 10 轮”。多出来的这一夜是给劣势方的 deadline extension。
- 和局是第三种结果；在零和博弈里，落后一方可能更偏好平局。配合“平票不出人”和“狼人可以空刀”，双方都可能通过不作为把游戏拖到平局。多死结算又按座位号顺序处理，猎人开枪/警徽移交可能形成链式反应，顺序不同会改变结果，但规则没有定义顺序。
- 其他隐藏规则：夜晚死亡者仍能完成当晚行动；女巫可以同夜双药；放逐投票允许自票；狼可以刀狼/自刀。这些都会改变激励，但目前没有在规则文本和提示词里统一说明。

**修改方向**：把白天顺序固定为“公布死亡 → 死亡触发（开枪/警徽）→ 胜负判定 → 竞选/遗言 → 发言 → 投票 → 胜负判定”；明确同时胜利的优先级（好人优先、狼人优先或平局）；把平局检查放在第 10 天结束或明确改成 11 轮；给平局加 tiebreak（剩余狼/神/民数量、突然死亡等），不要让“不作为”成为稳定策略；明确多死结算顺序或改为同时结算；统一女巫用药、自票、友伤、夜晚死亡行动的规则。

### 3.8 狼队治理：隐藏狼王 + 友伤

其他狼只看到“狼阵营”，不知道谁是狼王；同时规则允许刀狼/自刀。这形成一个 **common agency** 问题：单只狼可以单方面伤害整个狼队（刀队友、刀狼王、送人头），而狼队没有否决/共识机制。理性狼人通常不会这么做，但 LLM 可能因为误判或“钓鱼”策略这么做，增加噪声。

自刀钓解药/钓守护是一个有价值的策略，但需要明确它是设计意图；如果不是，应该禁止友伤或至少要求狼队共识。隐藏狼王本身影响不大（狼人知道队友 ID，一般不会互刀），但提示词里“including the Wolf King”与“不认得狼王”的表述需要统一。

## 4. 目标规则设计（建议）

> 以下为建议目标，落地前见第 7 节“待决策问题”。

### 4.1 狼人夜间行动

**推荐默认：每夜一个狼队击杀目标。**

实现选项：

- **A. 狼队私聊 + 共识**：新增一个私有狼队讨论阶段，最终提交一个目标；适合 LLM 模拟，能观察协调能力。
- **B. 同时秘密提案 + 多数**：每只狼秘密提交一个目标；统计后只结算一个目标；平票则空刀/随机（需决策）。适合不增加聊天阶段。
- **C. 首领狼决定**：固定一只狼（例如狼王或座位最小的狼）决定目标；简单但把协调问题变成单点决策。

不建议继续保留“每只狼各指一人、并集结算”。

**友伤**：

- 默认禁止狼刀狼/自刀。
- 如果保留自刀作为“钓鱼”策略，建议单独声明为 `self_sacrifice`，并要求狼队共识或公开代价；不要让单只狼可以无成本刀队友。

**数据模型**：

- `NightHistory.wolf_target: int | None`。
- 如需分析协调：`wolf_proposals: tuple[tuple[int, int], ...]`（私有，不进公开 observation）。
- 逐步弃用 `wolf_kills: list[int]`；或保留为只含 0/1 个元素的兼容字段。
- 更新 `WolfAction`、`wolf_do_night`、`fact_pack_named`、测试和提示词。

### 4.2 白天放逐投票

**推荐默认：同时秘密提交，投后公开完整 ballots。**

- 引擎收集所有存活玩家的 `voter -> target`，全部收齐后再计算 `vote_result`。
- 投票期间 `Observation.vote_tally` 为空；投票结束后 `Observation.ballots` 公开。
- 公开日志包含完整 ballots，包括平票/无人出局的情况。
- 弃权计为 `-1` 并公开（或至少公开“谁弃权”）。
- 禁止自票（推荐）；如果允许，明确写入规则和测试。
- 最低票数/quorum：建议“唯一最高票且至少达到存活人数的一半（向上取整）”，否则进入 runoff；或直接采用前两名 runoff。
- 平票：前两名 runoff；仍平票则随机平票者出局，或无人出局但给狼队一个代价（需决策）。不建议继续“平票免费不出人”。

**数据模型**：

- `DayHistory.ballots: dict[int, int]`（voter -> target；-1 弃权）。
- `DayHistory.vote_result` 保留 target -> `(count, voters)`，但只在全部投票后计算。
- `Observation.ballots: tuple[tuple[int, int], ...]`，仅投后出现。
- 新增 `DayHistory.runoff_ballots`（如采用 runoff）。

### 4.3 警长竞选

**推荐默认：全员投票 + runoff + 同时上警。**

- 所有存活玩家投票，包括候选人；候选人不能投自己（推荐）。
- 上警决策同时秘密提交，全部收齐后再公开候选人名单。
- 只有一名候选人时，仍然进行一次信任投票（过半数存活玩家同意才当选），避免“唯一候选人自动当选”被狼利用。
- 多人竞选：前两名 runoff；仍平票则随机或重投。
- 公开警长选举的完整 ballots。
- 警长权力：建议保留发言顺序，1.5 票改为 1 票或保留但加 runoff/制衡；这是一个待决策项。
- 警徽被撕毁后：考虑下一天重选，或明确本局永久无警长。

**数据模型**：

- `DayHistory.police_ballots: dict[int, int]`（voter -> candidate）。
- `DayHistory.police_vote_result: dict[int, tuple[int, list[int]]]`。
- `Observation.sheriff_ballots` 仅选举后公开。
- 上警阶段不要提前把 `sheriff_candidates` 暴露给后续玩家。

### 4.4 自爆

**推荐默认：自爆不再跳过投票，或跳过投票但让狼队下一夜少一刀。**

- 选项 A：自爆者出局并保留发言；当天剩余玩家继续发言和投票。自爆只是“认狼换节奏”，不能否决投票。
- 选项 B：自爆跳过投票，但狼队下一夜不能刀人（或只能刀一人但被守卫/解药克制），使代价单调。
- 选项 C：只允许当前票数最高的狼自爆（防止预判性救队友）。
- 保留“两狼自爆后警徽作废”，但把它改成始终伤害狼队的惩罚（例如额外公开信息/减少刀数），不要依赖警徽归属。

### 4.5 信息、遗言与观察层

- 新增统一 `PublicEvent` 流：死亡（含公开死因，如枪击/自爆/放逐；夜间狼刀 vs 毒杀可按设计隐藏）、枪击、自爆、警徽移交、警长选举、投票结果、遗言。
- `Observation` 增加 `public_events`、`ballots`、`sheriff_ballots`；`earlier_rounds` 包含候选人发言和警长选举结果。
- 投票期间不暴露实时票数；投后公开完整 ballots。
- 遗言：至少被放逐者 + 所有夜间死亡者（或提供有限“死亡留言”，例如只能留一条查验/怀疑）。如果担心信息过强，可限制字数/条数。
- 修改 `fact_pack_named` / `fact_wolves_killed` 的时态和触发条件：只在 Night 阶段注入，Day 用 “last night”。
- 人类 UI 和 LLM observation 从同一 `PublicView` 渲染，保证公开信息集一致；私有信息仍按座位裁剪。

### 4.6 守卫 / 女巫

- 取消“同守同救 = 死亡”，改为“解药优先/守护 + 解药 = 存活”；或让女巫在用药前看到守卫目标（信息换平衡）。
- 明确女巫是否同夜双药：
  - 推荐：每夜只能使用一种药（毒或救），与 `rule.md` 的“或”一致；或明确允许双药并调整强度。
- 明确夜晚死亡者是否仍能行动；推荐保留“同时行动”，但在规则文本和提示词中写清楚。
- 明确女巫被刀当夜能否用药/自救（首夜不能自救，后续可以）。

### 4.7 胜负、结算与和局

- 白天阶段顺序固定为：
  1. 公布死亡；
  2. 死亡触发（猎人/狼王开枪、警徽移交）；
  3. 胜负判定；
  4. 第一天警长竞选/遗言；
  5. 发言；
  6. 投票；
  7. 胜负判定；
  8. 入夜。
- 明确同时胜利优先级：
  - 推荐：好人优先（与当前代码一致），或
  - 平局，或
  - 按“最后完成的行动”判定。
  - 无论选哪个，写入规则、提示词和测试。
- 明确垂死开枪在胜负判定之前还是之后；推荐“死亡触发先结算，再判胜负”，但需要和同时胜利优先级一起定义。
- 平局：在第 10 天结束判定，或明确“11 轮”；推荐第 10 天结束。增加 tiebreak：
  - 比较剩余狼/神/民数量；
  - 或突然死亡：下一夜无守卫/无解药，先死人一方输；
  - 或直接判狼胜/好人胜（需产品决策）。
- 多死结算：定义固定顺序（例如按死亡原因优先级/座位号），或改为同时结算并明确链式开枪/警徽规则。
- 移除/限制“平票不出人”的免费现状；如果保留，给狼队一个代价（例如下一夜少一刀）或给好人补偿信息。

### 4.8 规则引擎可配置化（P2）

当前 `GameRule` 是部分配置：角色、阵营、夜晚/白天阶段名。特殊规则仍硬编码在 `GameRuleDefinitions`。如果后续要做规则变体/批量评测，建议逐步数据化：

- `Ruleset` 数据类：角色配比、阵营、夜晚/白天阶段列表、狼刀模式、投票平票规则、警长选举/权力、自爆代价、守卫/解药交互、女巫用药限制、遗言范围、胜负条件、同时胜利优先级、最大轮数、平局规则。
- `DecisionProtocol`：每个决策是同时/顺序、公开/私有、是否暴露中间结果。
- `WinCondition`：可组合的谓词（狼全灭/神全灭/民全灭/轮数）。
- 规则版本：`RULESET_ID` + `RULE_VERSION`；与回放格式版本绑定。

## 5. 开发计划

### 5.1 原则

1. **先版本化，再改规则。** 现有回放依赖 `seed + answers` 重放；规则一变，旧回放会重放出不同结果。必须先加规则/回放版本校验。
2. **先修信息集，再调平衡。** 如果人类和 LLM 看到的公开信息不同，胜率数据没有意义。
3. **一次只改一个机制，并跑批量对照。** 不要同时改狼刀、投票、警长后只看一局观感。
4. **更新现有测试，而不是只加新测试。** 当前有测试断言了“多刀并集/平票不出人/同守同救/第一天顺序”等旧行为，改规则时必须同步修改。
5. **规则文本、提示词、引擎、UI 观察必须同源。** 任何规则改动要同时更新 `rule.md`、`llm_interface.py` 的 RULES/ROLE_BRIEFING、`README.md` 和测试。

### 5.2 P0（下一步必须做）

| ID | 任务 | 主要文件 | 验收标准 |
|---|---|---|---|
| P0-0 | 规则/回放版本化 + 统一公开视图 | `engine.py`、`ui.py`、`tests/` | 导出含 `ruleset/rule_version`；`replay_file` 校验版本；旧回放有明确拒绝/迁移策略；人类/LLM 公开 observation 一致 |

### 8.3 术语表

- **Action economy（行动经济）**：每方每回合能执行的致命/保护/信息行动数量。当前狼 4 刀/夜 vs 好人 1 守 + 1 次解药 + 1 信息。
- **Public good（公共品）**：一只狼的击杀对全狼队有利，个体无成本；导致狼队“过度供给”击杀。
- **Status quo bias（现状偏好）**：平票不出人使“无作为”成为默认结果；有夜间击杀权的一方受益。
- **Minority veto（少数否决）**： cohesive 少数可以通过制造平票/分票阻止多数放逐。
- **Entry game / Spoiler effect（进入博弈/ spoiler）**：好人多上警会分票并减少好人选民，反而帮助集中的狼队。
- **Agenda setting（议程设置）**：警长决定发言顺序，影响信息和投票。
- **Outside option / Strategic exit（外部选项/策略性退出）**：自爆让即将输掉投票的狼主动退出并改变后续博弈。
- **Information asymmetry（信息不对称）**：狼队有私有互认/顺序刀口；好人只有公开信息和预言家查验。
- **Monotonicity（单调性）**：更多保护不应降低生存率；同守同救违反此性质。
- **Anti-coordination（反协调）**：守卫和女巫的动作重叠反而有害，且无法沟通。
- **Common agency（共同代理）**：狼队是共同利益团队，但单只狼可以单方面伤害团队。
- **Stackelberg / sequential move（序贯行动）**：后行动的狼/后投票者能看到前手结果，获得后手优势。
